02. 문제 정의

실제 어뷰저는 탐지 규칙을 피하기 위해 인간처럼 행동할 수 있다. 따라서 ‘플레이 시간이 너무 길다’, ‘행동 횟수가 너무 많다’ 같은 단일 특징만으로는 하드코어 이용자와 작업장을 구분하기 어렵다.

문제 A · 정상처럼 위장

작업장 계정마다 휴식, 퀘스트, 사냥터 변경을 넣어 단일 계정 분석에서는 정상 범위에 들어오도록 설계한다.

문제 B · 오탐 위험

하드코어 유저와 정상 길드도 긴 플레이 시간, 반복 행동, 특정 시간대 동시 접속 같은 특성을 가진다. 이를 작업장으로 오판하면 정상 이용자 경험을 해친다.

문제 C · 조직 단위 이상

이상은 개별 행동보다 계정 간 관계에서 더 명확할 수 있다. 여러 계정이 벌어들인 재화가 동일한 중간 계정과 Hub로 모이는 구조가 대표적이다.

핵심 가설: 개별 이상점수가 낮더라도 행동 동기화가 높고, 재화가 특정 노드로 집중되며, 거래/행동 패턴이 반복된다면 조직형 어뷰징 위험도가 높다.

03. Synthetic MMORPG 데이터 설계

실제 위메이드 내부 로그를 사용할 수 없으므로 재현 가능한 Synthetic Data Generator를 직접 구축한다. 중요한 것은 “가짜 데이터”가 아니라 탐지 가설을 검증할 수 있도록 정상군과 교란군을 의도적으로 설계하는 것이다.

3.1 계정군

유형초기 비율행동 특징탐지에서의 역할
Normal75%짧고 다양한 플레이, 불규칙 거래정상 기준군
Hardcore8%장시간 플레이, 높은 활동량, 행동 다양성 유지작업장과 혼동되는 오탐 테스트군
Guild7%특정 시간 동시 행동, 길드원 간 정상 거래행동 동기화 오탐 테스트군
Bot4%반복 간격, 낮은 행동 다양성전통적 이상탐지로 쉽게 잡히는 baseline
Farm5%겉보기 정상 행동 + Mule로 재화 전달핵심 탐지 대상
Mule0.8%수신 후 재전달 중심, 플레이 활동 적음세탁/중계 노드
Hub0.2%여러 Mule에서 최종 재화 집중조직의 종착점

작업장을 너무 쉽게 만들지 않는다

Farm 계정도 휴식, 맵 변경, 퀘스트 수행, 접속시간 노이즈를 갖게 한다. 단순 Isolation Forest만으로는 일부가 정상군에 섞이도록 의도한다.

정상군도 일부러 어렵게 만든다

Hardcore와 Guild 계정은 높은 활동량과 동기화 행동을 가지게 만들어 “오래 게임한다 = 작업장” 같은 단순 규칙이 실패하도록 한다.

04. 본인만의 이상탐지 기법: CARS

CARS(Coordinated Abuse Risk Score)는 계정 하나의 비정상성만 보는 것이 아니라, 조직적으로 함께 움직이는 정도를 여러 증거로 결합하는 위험 점수다.

CARS(u) = w1 · SyncScore(u) + w2 · FlowConcentration(u) + w3 · EconomicAnomaly(u) + w4 · RepetitionScore(u) + w5 · HubAffinity(u) 초기 가중치(설계안) w1=0.25, w2=0.30, w3=0.20, w4=0.15, w5=0.10 ※ 최종 가중치는 Synthetic Validation 결과로 조정
1

SyncScore

접속/사냥 종료/거래 시점이 다른 계정군과 얼마나 동시에 움직이는지 측정. 시간창 기반 동시성, 행동 시퀀스 유사도 등을 사용.

2

FlowConcentration

획득한 재화가 특정 Mule/Hub로 얼마나 집중되는지 측정. In-degree, weighted flow, HHI형 집중도 등으로 표현.

3

EconomicAnomaly

시장 가격 대비 비정상 거래가, 플레이 대비 거래량, 재화 회전 속도 등을 이용해 경제행위의 이상성을 계산.

4

RepetitionScore

행동 종류의 엔트로피, 동일 맵/행동의 반복도, 행동 간 시간 간격의 규칙성으로 자동화 흔적을 탐색.

5

HubAffinity

이미 의심되는 Hub/Mule와의 그래프 거리, 거래 빈도, 재화 전달 비율을 이용해 조직 연관도를 추정.

6

Evidence Bundle

최종 점수만 보여주지 않고 탐지 근거를 함께 제공. 운영자가 제재 전후를 판단할 수 있도록 설명 가능한 증거를 남김.

4.1 Baseline과의 비교

방법장점예상 한계프로젝트에서의 역할
Z-score / Rule설명 쉬움복합 패턴에 약함가장 단순한 기준선

06. 검증 설계

Synthetic 데이터의 장점은 정답 라벨을 알고 있다는 것이다. 따라서 단순 탐지 성공 사례만 보여주지 않고, 정상 유저를 얼마나 덜 오판하는지까지 검증한다.

핵심 평가 지표

  • Precision
  • Recall
  • F1 Score
  • False Positive Rate
  • Hardcore 오탐률
  • Guild 오탐률
  • Cluster 단위 탐지율

반드시 할 비교 실험

  • Rule vs Isolation Forest vs CARS
  • 개별 특징만 사용 vs 그래프 특징 추가
  • 경제 특징 제거 ablation
  • 동기화 특징 제거 ablation
  • 작업장의 랜덤 노이즈 강도별 성능 변화
  • Hardcore/Guild 비율 증가 시 오탐 변화
성공 기준: “CARS가 가장 높은 정확도를 냈다”가 아니라, 기존 단일 계정 기반 탐지에서 놓친 조직형 Farm을 추가로 찾으면서 Hardcore/Guild 오탐을 통제할 수 있는지를 증명한다.

07. 조사형 Streamlit 대시보드

분석 결과를 개발자용 표로 끝내지 않고 실제 운영자가 조사 순서를 정하고 근거를 확인하는 화면으로 만든다.

Risk Queue

위험도, 조직 크기, 재화 규모, 탐지 근거를 기준으로 조사 우선순위를 정렬.

Account Timeline

로그인부터 사냥, 이동, 거래, 로그아웃까지 시간순 행적을 확인.

Flow Network

Farm → Mule → Hub로 이어지는 재화 이동을 인터랙티브 그래프로 확인.

Evidence Card

“행동 동기화 상위 0.8%, 재화 86%가 동일 Mule로 이동”처럼 판정 근거를 요약.

False Positive Review

정상 길드·하드코어 유저가 왜 탐지됐는지 비교해 룰과 임계값을 조정.

Action Proposal

즉시 제재가 아니라 관찰, 추가 인증, 거래 제한, 수동 검토 후보 등 단계별 대응 시나리오 제안.

12. 문서에서 절대 과장하지 않을 부분

현재 구현 사용자가 실제 완료한 기능은 “구현 완료”로 표시한다.

설계 / 예정 아직 만들지 않은 CARS 성능, 탐지율, 오탐률, 대시보드 기능은 결과가 나온 뒤 업데이트한다.

실제 위메이드 내부 데이터나 나이트크로우 로그를 사용했다고 표현하지 않는다. 본 프로젝트는 공개적으로 알려진 MMORPG 경제·어뷰징 구조를 참고하여 설계한 Synthetic Simulation임을 명시한다.

GHOST FARM · Technical Proposal v0.1
본 문서는 포트폴리오용 기술기획서 초안이며, 구현 및 실험 결과에 따라 수치와 가중치, 검증 결과를 지속 업데이트한다.
